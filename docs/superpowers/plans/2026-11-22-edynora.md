# Edynora Implementation Plan

> Implement inline using the supplied master prompt as the execution authority.

**Goal:** Installable local marketing workflows with revision-bound approval and portable exports.

**Architecture:** Shared Zod contracts and bounded filesystem storage; focused domain modules; core service; thin CLI and Claude Code bridge.

**Tech Stack:** Strict TypeScript, Node >=22.12, Zod 4.6.7, remark 15.0.1, Vitest 5.1.1.

**Spec:** ../specs/2026-11-22-edynora-design.md and supplied master prompt.

## Global constraints

No publication, deployment, paid API calls, outbound marketing, incompatible source reuse or unsupported completion claims. Windows PowerShell is required. Offline templates must be labeled. All external data is untrusted.

## Review focus

- Traversal, symlinked workspaces and oversized input must fail without modifying external files.
- Edits and imported approval metadata must not preserve local export authority.
- Concurrent writers must fail cleanly rather than lose updates.
- Invalid dates, empty source text and unknown schema versions must fail validation.
- CSV formula input and Markdown/HTML content must remain inert or be escaped for export.

## Tasks

1. Research and licensing: record exact npm metadata and upstream license evidence; install with scripts disabled; audit graph and preserve notices.
2. Shared schemas/storage: create tests for brand validation, contract round trip, bounded reads, path confinement and locks; observe failure; implement `BrandSchema`, `VideoSchema`, `StateSchema`, `Store`.
3. Content and strategy: test all nine platforms, fidelity, unsafe instructions, 7/30-day calendars, all five email types; implement extraction, original templates and strategy with assumptions.
4. Core approval/export: test draft→review→approval→export, stale revisions, modification invalidation, concurrent store operations, CSV escaping; implement `Engine` methods and exporters.
5. CLI and plugin: process tests for every workflow and errors; implement fixed command grammar, JSON output, skills/commands and shell-free bridge. Run official plugin validation and local install smoke checks without a paid model request.
6. Release: document reproducible installs and limitations, generate schemas and license inventory; run strict typecheck/build/tests, package and clean install, execute demo, audit, and record exact results.

Each implementation task follows test→observed failure→implementation→verification. Record adjustments and evidence in FINAL_REPORT.md. No remote push or release.
